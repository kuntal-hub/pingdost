# Security policy

PingDost is a privacy-focused messenger, so we take vulnerability reports seriously.

## Reporting a vulnerability

**Please do not open a public issue for security problems.**

Report privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability** (GitHub private vulnerability reporting / security advisories).

Please include:

- the affected component (server, Android app, web client, crypto, mesh, calls) and version or commit;
- steps to reproduce, or a proof of concept;
- the impact you expect (e.g. plaintext exposure, key compromise, account takeover, metadata leak).

Do not include real users' data, and do not test against other people's accounts.

## What to expect

PingDost is maintained by a small team. We aim to acknowledge reports within 7 days, agree a fix and disclosure timeline with you, and credit you in the advisory unless you prefer otherwise.

## Scope

The project is in early development and is not yet released. Reports about the code in this repository are welcome at any stage. Cryptographic protocol issues in upstream libraries (for example vodozemac) should also be reported upstream.
