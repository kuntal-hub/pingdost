# Phase 04 — Protocol & shared contracts

**Depends on:** 02 (can run before or after 03) · **Platforms:** shared TS

## Goal
Define the versioned, transport-neutral wire protocol and the shared TypeScript contracts. Server, mobile, web, mesh and tests then all speak the same types.

## Read first
- REQ §4.3, §8.3, §11.2, §11.4 (packet fields), §16, §17 (limits)
- ARCHITECTURE A4, A5, A8

## Tasks
- [x] `packages/protocol`:
  - add `buf.yaml` and `buf.gen.yaml` (protoc-gen-es, target ts);
  - add the `@bufbuild/buf` and `@bufbuild/protobuf` dev and runtime deps (check current versions);
  - script `pnpm --filter @pingdost/protocol gen`;
  - **commit the generated code** under `src/gen/`.
- [x] **Schemas** `proto/pingdost/v1/`:
  - `packet.proto`: `TransportPacket` (fields per ARCHITECTURE A4) and `PacketKind` (ENVELOPE, ACK, MESH_ACK, MESH_CHUNK, EPHEMERAL, HELLO); flags.
  - `envelope.proto`: `Envelope`, `CryptoType`.
  - `content.proto`: `Content` with `ContentHeader` and the oneof bodies Text, Reaction, Edit, Delete, Receipt (DELIVERED | READ, with message ids and an optional hop count), AttachmentManifest, GroupControl, RoomKey, SyncChunk, CallSignal, SessionReset, KeyChange, plus `padding`.
    - Keep later-phase bodies minimal but present; later phases may extend them by adding fields only.
  - `ws.proto`: `ClientFrame` / `ServerFrame` oneofs (Auth, AuthOk, Send, Accepted{status: STORED | DELIVERED_TRANSPORT}, Deliver, Ack, Presence, Typing, Ephemeral, OtkLow, Revoked, Error{code, retryable}, Ping/Pong).
  - `mesh.proto`: `MeshHeader` (packet id, created, expiry, dst routing token, hop budget, origin token, chunk ref). It is filled out in Phase 23.
- [x] **Codec helpers** (`src/codec.ts`):
  - `encode*`/`decode*` wrappers enforcing `ENVELOPE_MAX_BYTES`, the major-version check, expiry checks and required fields;
  - a `ProtocolError` with codes;
  - **padding policy** helper: pad Content to buckets, e.g. 256 B / 1 KiB / 4 KiB / 16 KiB.
- [x] **IDs:** `uuidv7()`, `envelopeIdFor(messageId, recipientDeviceId)` (UUIDv5 with a fixed namespace), and byte↔string helpers. Use a library that works in RN, Node and browser (check `uuid` versions; RN needs `crypto.getRandomValues`, via expo-crypto or a polyfill note).
- [x] **`packages/shared-types`:**
  - Zod v4 REST DTOs for the auth, device, keys, profile, groups, attachments and pairing endpoints. Later phases may stub these and extend them;
  - an `ErrorCode` enum;
  - a problem+json type;
  - the pagination type;
  - `MessageState` (REQ §8.3 names exactly) and its legal transitions table.
- [x] **`packages/crypto`:** finalize the `CryptoProvider` interface (from the Phase 2 draft). Add `runCryptoConformance(provider)`, a reusable suite with the Phase 2 scenarios, and run it against the WASM provider in Vitest.
- [x] **`packages/api-client`:**
  - a `createApiClient({ baseUrl, getAccessToken, onRefresh })` fetch wrapper;
  - problem+json error mapping, timeouts (AbortController), and bounded retries on idempotent GETs;
  - typed endpoint functions generated by hand from `shared-types` (health only for now).
- [x] **`packages/test-fixtures`:** golden protocol vectors (JSON ↔ base64 bytes) for every message type, and a test that decodes each one.
- [x] CI: add `buf lint`, plus `buf breaking --against '.git#branch=main'` once main has this phase.

## Key files
`packages/protocol/{buf.yaml,buf.gen.yaml,proto/pingdost/v1/*.proto,src/gen/**,src/codec.ts,src/ids.ts}`, `packages/shared-types/src/*`, `packages/crypto/src/{types.ts,conformance.ts}`, `packages/api-client/src/*`, `packages/test-fixtures/protocol/*`

## Out of scope
Server endpoints, engine logic.

## Done when
- `pnpm --filter @pingdost/protocol test`: round-trip of every message; oversized, expired, malformed and wrong-version inputs are rejected.
- `buf lint` is clean, and the generated code is up to date (CI runs `gen` and checks git is unchanged).
- The crypto conformance suite passes on WASM.
- `pnpm lint typecheck test` passes.
