# 0006 — Wire protocol encoding details

- **Status:** Accepted
- **Date:** 2026-10-19
- **Phase:** 04
- **Approved by user:** n.a.

## Context
ARCHITECTURE A4 locks Protobuf (protobuf-es v2 + buf), the three layers (TransportPacket → Envelope → Content) and the WebSocket frames. Phase 4 had to fix the details every later phase builds on: versioning, ID encoding, 64-bit types in TypeScript, size limits, expiry, padding, flags and error codes. REQ §4.3 (transport-neutral protocol), §8.3 (states), §11.4 (packet fields), §16.3 and §17 apply.

## Options considered
| Question | Option | Pros | Cons |
|---|---|---|---|
| int64 in TS | **bigint (protobuf-es default)** | Exact; Hermes, browsers and Node support BigInt | `BigInt(ms)` at the boundary |
| | `jstype = JS_STRING` | No BigInt needed | Strings for numbers; easy to misuse |
| | `double` for times | `number` in TS | Breaks A8 (int64 on the wire); 8 bytes always |
| Hiding message length | **`padding` field in Content, to buckets** | Inside the E2EE ciphertext; plain protobuf | Some sizes cannot be hit exactly (handled below) |
| | Byte padding outside protobuf (ISO 7816-4) | Exact sizes | A second framing layer to parse |
| | No padding | Simplest | Ciphertext length reveals message length |
| WS error codes | **String codes shared with REST (`ErrorCode`)** | One list for REST and WS | Not checked by `buf breaking` |
| | Proto enum | Typed on the wire | A second list to keep in sync |

All new dependencies are permissive (checked 2026-10-19): `@bufbuild/buf` 1.74.0 (Apache-2.0), `@bufbuild/protobuf` 2.16.0 (Apache-2.0 AND BSD-3-Clause), `@bufbuild/protoc-gen-es` 2.16.0 (Apache-2.0), `uuid` 14.0.3 (MIT). No cost.

## Decision
1. **Layout.** `packages/protocol/proto/pingdost/v1/{packet,envelope,content,ws,mesh}.proto`, package `pingdost.v1`. `buf lint` uses STANDARD (run by the package's `lint`); `buf breaking` uses WIRE_JSON (wire and JSON compatibility, since the golden vectors include JSON). Generated code (`src/gen/`, protoc-gen-es `target=ts`) is committed; CI regenerates it and fails on any diff.
2. **Versioning.** `TransportPacket.version`, `ContentHeader.version` and `Auth.protocol_version` carry the major version (1). Decoders reject any other major version (`UNSUPPORTED_VERSION`); 0 counts as missing. Within v1, changes add fields, enum values or oneof members only.
   - Unknown fields are kept. A oneof body this build does not know is `UNKNOWN_BODY`, so the client can say "update needed".
   - Unknown `PacketKind` values pass the codec; consumers ignore them. Unknown flag bits are ignored.
3. **64-bit integers** are `bigint` in the generated types. REST DTOs and app code keep epoch milliseconds as `number` (A8); convert with `BigInt(ms)` / `Number(value)` at the boundary.
4. **IDs.** Users and devices also use UUIDv7; device IDs are generated by the client. IDs are 16 bytes in protobuf and canonical lowercase strings in REST and storage.
   - `envelopeId = UUIDv5(7a9f4a0a-78e5-4e69-99d3-4cd3fac446d6, messageId bytes ‖ recipientDeviceId bytes)`. The namespace never changes; a golden test pins one value.
5. **Size limits** (all derived from `ENVELOPE_MAX_BYTES`, default 64 KiB) are checked before parsing:
   - an encoded Envelope ≤ `ENVELOPE_MAX_BYTES`, and so is every packet payload except `MESH_CHUNK` (one 65,552-byte ciphertext chunk + 256 bytes, ADR 0004);
   - a TransportPacket ≤ its payload limit + 256 bytes; a WS frame ≤ that + 256;
   - an encoded, padded Content ≤ `ENVELOPE_MAX_BYTES` − 1024 (room for Olm/Megolm framing and the other Envelope fields).
6. **Expiry.** `expires_at_ms` must be after `created_at_ms`; a packet is expired when `expires_at_ms ≤ now`. Packets inside `Send`, `Deliver` and `Ephemeral` frames are checked too. Callers may pass `nowMs` (e.g. a skew-corrected clock).
7. **Padding.** `encodeContent` zero-pads through `padding` (field 15, so a one-byte tag) to 256 B, 1 KiB, 4 KiB or 16 KiB, then multiples of 16 KiB, capped at the Content limit.
   - A gap of 1–2 bytes, or one that lands on a varint-length boundary, cannot be filled exactly; that size moves to the next bucket. At the cap it lands 1–2 bytes under.
   - The padding is inside the E2EE ciphertext; decoders ignore it.
8. **Ephemeral and flags.** `PACKET_KIND_EPHEMERAL` marks a packet (an Envelope) that is relayed only to an online recipient and never stored: call signaling and history-sync chunks. The `flags` bitmask defines `URGENT` (an incoming call: the server may send a call-priority push wake, Phase 26). A4's "flags (e.g. EPHEMERAL)" became the kind, so the two cannot disagree.
9. **WebSocket frames.**
   - `request_id` correlates a client frame with its reply.
   - The error frame is `ServerError` (so the generated type does not shadow the global `Error`), with a string `code` from `@pingdost/shared-types` `ErrorCode`, shared with problem+json, plus `retryable` and a fixed `message`.
   - `Accepted` carries `packet_id`, `envelope_id` and `STORED | DELIVERED_TRANSPORT`. `Ack` lists envelope IDs (the mailbox keys) and is also the `PACKET_KIND_ACK` payload.
   - `Typing` lists recipient device IDs; the server stamps the sender device from the socket.
10. **Golden vectors.** `packages/test-fixtures/protocol/v1.json` holds one vector per message type, per oneof body, per packet kind and per crypto type (JSON + bytes). It is rewritten only by `make-vectors`, for a deliberate wire change.
11. **React Native prerequisites.** protobuf-es needs `TextEncoder` and `TextDecoder` (with `fatal: true`), and `uuid` needs `crypto.getRandomValues`, on `globalThis`. Hermes does not always ship `TextDecoder`, so `apps/mobile` installs both polyfills before it first uses `@pingdost/protocol`.

## Consequences
- Every encoder and decoder throws `ProtocolError` with a code and the proto field name, never payload bytes (A10).
- `@pingdost/shared-types` owns `ErrorCode`, problem+json, pagination, `MessageState` (REQ §8.3 names) and its transition table, plus stub DTOs that later phases extend.
- Updated: ARCHITECTURE A4 and A8; phase files 05, 06, 08, 09 and 10.

## Evidence
- `pnpm --filter @pingdost/protocol test`: 77 tests, covering round trips of every message, the golden vectors, and the rejection of oversized, expired, malformed, wrong-version and unknown-body inputs.
- Padding was checked for every text length from 0 to 1,199 bytes and around each bucket edge; every result is an allowed size.
- `buf lint` is clean. `buf generate` reproduces the committed code byte for byte.
