# 0022 — Backup format, recovery phrase and replacing the primary phone

- **Status:** Accepted
- **Date:** 2026-10-31
- **Phase:** 19
- **Approved by user:** n.a.

## Context
REQ §6.2 (one primary phone; new-primary activation must be authenticated, auditable and replay-resistant), §6.3 (opt-in recovery, an encrypted local export under a high-entropy phrase, versioned and integrity-checked, never kept by the server; an authorized device may approve a replacement; honest copy about irrecoverable history), §7.5 (recovery keys in OS secure storage; nothing in logs) and §21 ("user loses every device"). ADR 0003 limits what may be backed up: the account identity key and Megolm inbound sessions, never a device Olm account, Olm sessions or outbound Megolm sessions. ADR 0008 makes `users.accountIdentityKey` the anchor every device certificate hangs from.

## Options considered
| Question | Option | Pros | Cons | License | Cost |
|---|---|---|---|---|---|
| Key from the phrase | **Argon2id in the Rust crate (RustCrypto `argon2` 0.6.0)** | One implementation on every platform (native + WASM), memory-hard, bounded parameters | New dependency; no independent audit stated in its README | MIT OR Apache-2.0 | free |
| | PBKDF2 / scrypt from the JS side | No Rust change | Per-platform JS crypto; PBKDF2 not memory-hard | — | — |
| Body encryption | **The attachment STREAM (ADR 0004): XChaCha20-Poly1305, 64 KiB chunks** | No new primitive; constant memory; truncation and reordering detected | Empty AAD (the header is bound another way, below) | Apache-2.0 OR MIT | free |
| Body layout | **Length-prefixed frames: JSON records + raw file bytes** | Versioned, streamable, files without base64 | Our own framing (not crypto) | — | — |
| | A SQLite copy | Byte-exact | SQLCipher-keyed, phone-only; carries forbidden device state | — | — |
| Phrase | **24 BIP39 words (`@scure/bip39` 2.4.0), 256 bits; only the entropy enters the KDF** | Standard word list, checksum catches typos | Wallet users may confuse it with a crypto wallet phrase | MIT | free |
| Keeping the phrase | **Entropy in SecureStore; shown once; later backups reuse it** | REQ §7.5; the monthly reminder becomes one tap | An unlocked phone can make new backups (it still cannot show the phrase) | — | — |
| | Never stored, new phrase per backup | Nothing on the phone | A new phrase to write down every time | — | — |
| Old-phone approval | **Old phone seals the account key to the new phone over a one-off Olm session; the user compares a 6-digit code** | Olm only (no new primitive); the server cannot swap keys unnoticed | Both phones online; no history (back up first) | — | — |
| Who may approve | **Only the active primary** | It alone holds the account key (linked browsers never do, ADR 0019) | A lost primary needs a backup | — | — |

## Decision
1. **File `pingdost-backup-YYYY-MM-DD.pdbk`** (`packages/backup`):
   - header, 69 bytes, big-endian: magic `89 50 44 42 4B 0D 0A 1A`, format version `1` (u16), KDF `1` = Argon2id v0x13, memory KiB (u32), passes (u8), lanes (u8), salt length `32`, salt, the 19-byte STREAM nonce prefix. No account data in clear;
   - key = `Argon2id(phrase entropy, salt)`, 32 bytes; defaults **64 MiB, 3 passes, 1 lane** (RFC 9106's second recommendation with one lane; about 0.5 s in WASM on the dev PC). The crate refuses memory > 1 GiB, passes outside 1–16, lanes outside 1–8 and salts outside 16–64 bytes, so a crafted header cannot exhaust a phone;
   - body = the attachment STREAM under that key: every chunk but the last is 64 KiB of plaintext; the last is shorter (possibly empty) and flagged, so a cut file fails;
   - plaintext = frames `type (u8) ‖ length (u32) ‖ payload`: type 1 a JSON record (≤ 1 MiB), type 2 the next ≤ 64 KiB of the file announced by the preceding `file` record;
   - records, in order: `manifest` (format, createdAt, userId, the public account key, the app, `includesFiles`, **the header's SHA-256**), `identity` (the account identity key secret), `conversation`, `message`, `group` (avatar base64), `megolm` (each inbound session as `exportAt(firstKnownIndex)` with its sender, sender key and seen indices; no `sharedAt`), `directory` (contacts' verified keys and the verified flag), `settings` (the app's local notification and attachment preferences), optional `file` records (attachment and preview ciphertext from the vault, with message, conversation and role), and **`end`** (the frame count and the SHA-256 of every frame before it). Unknown record types are skipped (add-only).
   - **Never in a backup:** the Olm account, Olm sessions, outbound Megolm sessions, the outbox, receipts owed, seen IDs, history-sync cursors, the fallback-key rotation time.
2. **Reading:** the header decides the KDF; the first chunk failing means `wrong_phrase`; any later failure, a bad frame, a header hash or `end` mismatch, or data after `end` is `corrupt`; a body that is not `n × 65,552 + (16…65,551)` bytes is `truncated`. `restoreFromBackup` reads the whole file once before writing anything (pass 1), then writes in batches of 250 records into an **empty** store under the new device's pickle key.
3. **Restored phone = new device** (ADR 0003): a new Olm account and device ID certified by the restored account key, so no ratchet state is ever reused. "1:1 sessions marked stale" therefore means: there are none. Outgoing messages that never left the old phone (`local_queued`, `sending`, `waiting_for_nearby_route`) become `failed`; restored message IDs are written as seen, so a resend is stored once; contacts' directories come back with `fetchedAt = 0` and are refetched before use.
4. **Announce:** once the engine runs and its keys are published, the restored phone sends a `SessionReset` to every device of each direct-chat peer (`engine.announceNewDevice`). A receiver resolves the unknown device (directory refresh), then `resendTo` also sends it the recent direct messages that reached the server but **no device of that user confirmed** (`sent_to_server` / `relayed`, within the retention window): what the lost phone missed.
5. **Phrase:** 24 BIP39 English words from 32 random bytes made on the phone; spacing and case are ignored; BIP39's seed derivation is not used. Shown once (not selectable, no copy button, the keyboard asked not to learn it), then checked with three random words. Its entropy is kept in SecureStore (`pingdost.backup-phrase.v1`) so later backups reuse it; "Make a new recovery phrase" replaces it (older files still need the old one). Never sent, logged or put in analytics. The file is saved to a folder the user picks (Android SAF) or the share sheet; PingDost never receives it.
6. **Replacing the primary** (`primary_transfer_requests`, TTL 10 min; `apps/server/src/modules/device/primary-transfer.ts`). Every path needs a **login from the last 15 minutes** (`RECENT_LOGIN_REQUIRED`; a refresh never makes a login recent), a device-less session, a per-account budget (10 per hour) plus per-IP route limits, and is audited.
   - **(a) Approve from the old phone.** `POST /v1/devices/primary-transfer` (keys + a one-time key signed by the new device) → a `PrimaryTransferRequested` WS frame to the account's online devices and a push wake to its phones. The old phone lists it (`GET …/primary-transfer`), shows the code `SHA-256(pingdost/primary-transfer-code/v1 ‖ requestId ‖ deviceId ‖ curve25519 ‖ ed25519)` as six digits, and on approval sends the device certificate and an Olm pre-key message (to that one-time key) carrying `pingdost/primary-transfer-payload/v1 ‖ {requestId, userId, accountIdentityKeySecret}`. The new phone polls, opens it, checks the key against the account's public key and the certificate, and completes with a proof of possession over a fresh nonce; **only then** is the approver revoked and the new phone registered (`keyVersion` bumped). Approve, deny and complete are single-use; a denied, expired or completed request answers `TRANSFER_ALREADY_USED` / `TRANSFER_EXPIRED`. **Policy:** only the active primary approves; any device of the account (a linked browser too) may deny.
   - **(b) Restore + email code.** `POST /v1/devices/primary-replace/otp`, then `POST /v1/devices/primary-replace {mode: 'restore', otp, …registration}`: the certificate must verify under the account's current key (else `IDENTITY_KEY_MISMATCH`, checked before the code so a wrong backup does not burn it); the active primary is revoked, linked browsers stay (same key). The phone checks the backup belongs to the account and verifies the whole file **before** this call.
   - **(c) Start fresh + email code.** `mode: 'fresh'` with a new `accountIdentityKey`: every active device is revoked (their certificates came from the old key), the account key is replaced, the new phone registers. Contacts see "safety number changed".
   - Audit events: `primary_transfer_request|approve|deny|complete`, `primary_replace`, `identity_reset`.
7. **Key-change notices:** a changed account key keeps the existing "safety number changed" notice (direct and group chats) and resets verification. A **new primary under the same key** (a or b) adds `primary_device_changed` ("… moved to a new phone. The safety number is unchanged.") to the direct chat only, and **keeps** verification: the safety number did not change, and only the account key's holder can certify a phone. Linked-browser changes add no notice. Other devices update their caches when the new phone writes to them (`SessionReset`) or when a send to the revoked phone fails.
8. **On the old phone:** a revoked phone wipes its chats (as before) and now also deletes the account key and the stored phrase. Settings → Log out → **Remove data from this phone** revokes this device (online only), then deletes the database, files, and every SecureStore item.

## Consequences
- New package `@pingdost/backup` (format, phrase, export/restore over `EngineStore`, the transfer crypto shared by the app, the sim client and tests). New store read `listInboundGroupSessions(groupId)` in the contract (memory, Dexie, SQLCipher stores).
- `CryptoProvider.deriveBackupKey`; conformance scenario `backup-kdf` (known answer from OpenSSL's Argon2id). WASM and Android bindings regenerated.
- Protocol (add-only): `ServerFrame.primary_transfer_requested = 13`; `primaryTransferCodeMessage`, `primaryTransferCode`, the transfer payload codec; vector `server-frame/primary-transfer-requested`.
- Error codes `RECENT_LOGIN_REQUIRED` (403), `TRANSFER_NOT_FOUND`, `TRANSFER_EXPIRED`, `TRANSFER_ALREADY_USED`; OTP purpose `primary_replace`.
- Path (a) carries no history; the app says to back up first and use (b). A history hand-over between two online phones (the Phase 18 sync) is left for Phase 27.
- If the app dies after the server accepted a replacement but before the restore finished, the next start resumes the device with a partial history (re-run the restore by hand). Tracked for Phase 27.
- Phase 27 also: `FLAG_SECURE` on the phrase screen (screen capture), a backup-file round trip across app versions, and the phone-change flows on a real second phone.
