# PingDost — Locked Architecture Decisions

This file records the decisions that implement the requirements baseline (`privacy_first_messaging_app_requirements.md`, called **REQ** below). Phase files reference sections by ID (A1…A12).

- ⚠ marks a deliberate deviation from REQ; each one is also logged in `docs/CHANGES.md`.
- To change a decision, write an ADR in `docs/decisions/` and update this file.

---

## A1. Repo & tooling
- **Monorepo:** pnpm workspaces + Turborepo. Node 24 LTS. TypeScript `strict` + `noUncheckedIndexedAccess`. ESLint flat config (typescript-eslint) + Prettier. Vitest everywhere.
- **Internal packages** are "just-in-time" packages: `exports` point at TS source, and the consuming app's bundler compiles them (Metro, Vite, tsup). There is no per-package build step unless a package needs one, such as the protobuf codegen output, which is committed.
- **Package scope:** `@pingdost/*`.
- **Layout:**
```text
apps/
  mobile/          Expo (Android first; iOS deferred), Expo Router
    modules/       Expo local native modules (nearby, later others)
  web/             Vite + React
  server/          Fastify API + WS gateway; src/main.ts (API) and src/worker.ts (jobs)
crates/
  pingdost-crypto/ Rust wrapper over vodozemac (+ attachment AEAD if ADR says so)
packages/
  config/          Zod-typed env parsing; `@pingdost/config/public` = client-safe constants
  shared-types/    Zod REST DTOs, error codes, problem+json type, ID helpers
  protocol/        protobuf schemas (buf) + generated protobuf-es code + codecs
  crypto/          CryptoProvider interface + wasm impl (ubrn wasm2, generated code committed) + interop tests
  crypto-native/   RN Turbo Module generated by uniffi-bindgen-react-native (Phase 3)
  message-engine/  outbox, state machine, sessions, fan-out, dedupe, receive pipeline
  transport/       Transport interface, WsTransport, TransportRouter, NearbyTransport iface
  mesh-protocol/   hop/TTL/dedupe/relay store/chunking/relay policy
  attachments/     chunked encryption, manifests, size/MIME rules, compression decisions
  call-engine/     1:1 call state machine + signaling (Phase 25)
  auth/            auth/session contracts shared by server and clients
  api-client/      typed REST client (fetch) used by web + mobile
  ui-tokens/       shared design tokens (colors, spacing, radii) for NativeWind + Tailwind
  test-fixtures/   protocol + crypto test vectors
tools/
  sim-client/      headless Node client (engine + wasm crypto) for integration tests and mesh simulation
docs/              this file, ROADMAP, PROGRESS, CHANGES, phases/, decisions/, ops/
```
- ⚠ **No `apps/worker`.** The worker is `apps/server/src/worker.ts`, which reuses the server modules. `RUN_WORKER_IN_PROCESS=true` runs the jobs inside the API process, for small hosts.
- **Local infra:** `docker-compose.yml` runs MongoDB 8 as a single-node replica set (needed for majority writes and transactions), Valkey 8 (Redis-compatible) and Mailpit (SMTP capture with a web UI on :8025). Two compose profiles add services later: `s3` (MinIO, Phase 14) and `calls` (coturn, Phase 25).
- **Phones reaching the dev server:** use the PC's LAN IP (`EXPO_PUBLIC_API_URL=http://192.168.x.x:3000`, cleartext allowed only in dev builds) or a free Cloudflare quick tunnel (`cloudflared tunnel --url http://localhost:3000`).
- **CI:** GitHub Actions, free for the public repo. Jobs: format check, lint, typecheck, unit tests, and integration tests. The integration job starts Mongo (replica set) and Valkey from `docker-compose.yml` (`docker compose up -d --wait mongo valkey`), because service containers cannot pass `--replSet`.

## A2. Backend (modular monolith)
- **Framework:** Fastify 5 + `fastify-type-provider-zod` (Zod v4).
  - One Fastify plugin per module under `apps/server/src/modules/<name>/` (`routes.ts`, `service.ts`, `repo.ts`, `index.ts`).
  - Errors are problem+json: `{ type, title, status, code, detail? }`, with codes from `@pingdost/shared-types`.
- **Modules** (from REQ §15): auth, account, device, keys (crypto directory), gateway (WS), delivery, attachments, groups, calls, pairing, mesh, push, security (rate limits, blocks, reports, audit).
- **Logging:** pino with `redact` paths for the authorization and cookie headers and for any field named `password`, `otp`, `token`, `refreshToken`, `idToken`, `ciphertext`, `payload`, `sdp`, `*Key` or `secret`. Request IDs are on. A test asserts the redaction works.
- **MongoDB:** official `mongodb` driver (no Mongoose).
  - Each repo calls `ensureIndexes()` at startup.
  - `maxPoolSize` stays small (Atlas M0).
  - Collections: users, sessions, email_otps, devices, one_time_keys, groups, blocks, abuse_reports, security_events (TTL), pending_envelopes, attachments, pairing_requests, push_tokens, job_locks, primary_transfer_requests.
- **Redis:** `ioredis`, configured by a single ⚠ `REDIS_URL` (native protocol, `rediss://` for Upstash). This replaces REQ's `UPSTASH_REDIS_URL` and `UPSTASH_REDIS_TOKEN`.
  - Prod runs on either Upstash or self-hosted Valkey; ADR from Phase 8 data, decided in Phase 20.
  - Free Upstash allows 500K commands/month, so these stay **in-memory** (single instance): presence, typing, rate limits, connection registry, call state and the ephemeral relays.
  - Redis is used only for the offline hot mailbox (A3).
  - A command-counting wrapper exposes Redis usage as a metric.
- **Jobs:** ⚠ no BullMQ or QStash. Use a small scheduler (`setInterval` + Mongo `job_locks` leases with an owner and expiry), with jobs that are idempotent and retryable. Jobs: migration, reaper, attachment janitor, OTP/pairing cleanup, OTK low-water notices.
- **Auth:**
  - **Passwords:** `@node-rs/argon2` (Argon2id; params from env, defaults m=19456 KiB, t=2, p=1).
  - **Access tokens:** HS256 JWTs (`jose`) carrying `sub` (userId), `did` (deviceId) and `sid` (session); default TTL 15 min.
  - **Refresh tokens:** opaque random 32 bytes, stored as an HMAC-SHA256 hash (server pepper), rotated on every use. Reuse of an old token revokes the whole token family.
  - **Google:** the client obtains an ID token, and the server verifies it with `jose.createRemoteJWKSet` against Google's JWKS. Accepted audiences are listed in `GOOGLE_CLIENT_IDS`. There is no redirect callback. ⚠ Facebook is deferred.
  - **OTPs:** 6 digits, stored as HMAC hashes, single-use, with a TTL, max attempts, a resend cooldown and per-email/per-IP limits.
- **Email:** an `EmailProvider` adapter chosen by `EMAIL_PROVIDER`:
  - `console` (dev only; content hidden unless `EMAIL_CONSOLE_SHOW_CONTENT=true` and not production);
  - `smtp` (nodemailer: Mailpit in dev, Brevo free 300/day, Zoho);
  - `zeptomail` (HTTP API; the first 10K emails are free).
- **Push:** a `PushNotifier` adapter with `fcm` (FCM HTTP v1, service account) and `webpush` (VAPID); `apns` comes in the iOS track.
  - Payloads are a **content-free wake** (`{"t":"wake"}` or `{"t":"call"}`), coalesced per device.
- **Attachment staging:** an `AttachmentStore` interface with two adapters:
  - `fs` (VPS disk, REQ §22; signed HMAC URL tokens served by the API with range support);
  - `s3` (AWS SDK v3; R2- and MinIO-compatible; presigned multipart).
  - ⚠ This resolves the REQ §10.3 vs §22 conflict.
- **Avatars:** Cloudinary (free) for **user profile avatars only**, using signed client uploads. ⚠ Group name, avatar and description travel **E2EE inside group control messages**; the server stores none of them.
- **User discovery:** **exact-match username lookup only**, rate-limited. No contact upload and no fuzzy search.

## A3. Delivery mailbox (REQ §9)
- **Durability chain.** The sender's local **outbox is the durable copy** until the server replies `Accepted`, which it sends only after one of:
  - (a) the recipient device's transport ACK (online path; no Redis write), or
  - (b) a successful Redis write, or
  - (c) a successful Mongo write (the fallback when Redis is down).
  - If neither store is available, the server returns a retryable error and the sender retries. The server never holds the only copy in memory.
- **Online path.** The server forwards `Deliver` to the recipient's live socket and waits `MESSAGE_ONLINE_ACK_TIMEOUT_MS` (default 5000). On ACK it replies `Accepted{delivered_transport}`. On timeout it falls back to the offline path.
- **Offline path (Redis keys).** Written in one MULTI, then `Accepted{stored}`, then a push wake:
  - `env:{envelopeId}`: serialized envelope, with a safety TTL of `MESSAGE_REDIS_STAGE_SECONDS + MESSAGE_MIGRATION_GRACE_SECONDS`;
  - `mbx:{recipientDeviceId}`: a ZSET of envelope IDs scored by createdAt;
  - `due`: a ZSET of envelope IDs scored by `createdAt + STAGE`.
- **Migration job.** Runs every `MESSAGE_MIGRATION_POLL_SECONDS` (default 300; startup validation requires ≤ GRACE/3).
  1. `ZRANGEBYSCORE due -inf now`.
  2. For each ID, take a `SET lock:{id} NX PX` lease and `GET env:{id}`.
  3. If the envelope is missing (it was already acknowledged), `ZREM` it from `due`.
  4. Otherwise upsert it into Mongo `pending_envelopes` with `$setOnInsert`, writeConcern majority and the **original** createdAt and expiresAt.
  5. Read it back to verify.
  6. Only then `MULTI DEL env + ZREM mbx + ZREM due`.
- **Fetch on connect.** The server merges `mbx:{device}` (MGET) with Mongo `find({recipientDeviceId, expiresAt > now})`, dedupes by envelopeId, and streams batches in createdAt order.
- **ACK.** Idempotently deletes the envelope from both stores. Unknown IDs are a no-op.
- **Expiry.** `expiresAt = serverReceivedAt + MESSAGE_MAX_RETENTION_SECONDS`, set once and never reset. Enforced by a Mongo TTL index (backstop) plus an explicit reaper, which also removes orphaned Redis ZSET members.
  - Senders compute `expired_undelivered` locally (no delivered receipt by createdAt + max retention), so the server never needs to store expiry notices.
- **Delivery receipts are E2EE content messages** from the recipient device, governed by the user's receipt setting. The server `Accepted` only means `sent_to_server`.
- **Idempotency.** `envelopeId` is deterministic per (messageId, recipientDeviceId), so retransmits reuse it. The server dedupes on envelopeId and clients dedupe on messageId, which gives exactly one logical delivery.
- **Metrics** (`/metrics`, token-protected):
  - mailbox: Redis stage count, due backlog, oldest item age, Mongo pending count;
  - jobs: migrations, retries/failures, expired deletes;
  - traffic and cost: Redis commands, WS connections, duplicate rate, attachment bytes/age, deletion failures.

## A4. Wire protocol
- **Encoding:** Protobuf (protobuf-es v2 + `@bufbuild/buf` from npm) in `packages/protocol/proto/pingdost/v1/`.
  - The generated code is committed. CI runs `buf lint`, and `buf breaking` once main exists.
- **Layers:**
  - `TransportPacket` (visible to server and relays): `version`, `packet_id` (UUIDv7 bytes), `kind` (ENVELOPE, ACK, MESH_ACK, MESH_CHUNK, EPHEMERAL, HELLO), `dst` (device ID or mesh routing token), `created_at_ms`, `expires_at_ms`, `hop_budget`, `flags` (bitmask: URGENT), `payload`.
  - `Envelope` (visible to the server): `envelope_id`, `sender_device_id`, `recipient_device_id`, `crypto_type` (OLM_PREKEY | OLM | MEGOLM), optional `group_id`, `ciphertext`.
  - `Content` (**inside** the E2EE ciphertext): header (`message_id`, `conversation_id`, `sender_user_id`, `sent_at_ms`, optional `reply_to`, protocol version), a oneof body {Text, Reaction, Edit, Delete, Receipt, AttachmentManifest, GroupControl, RoomKey, SyncChunk, CallSignal, SessionReset, KeyChange}, and `padding`.
  - WS frames: `ClientFrame` / `ServerFrame` oneofs (Auth, AuthOk, Send, Accepted, Deliver, Ack, Presence, Typing, Ephemeral, OtkLow, Revoked, ServerError, Ping/Pong).
- **Ephemeral relay.** Call signaling, history-sync chunks and typing are **ephemeral**: the server relays them in memory to online devices only and never writes them to Redis or Mongo. Ephemeral envelopes travel as `PACKET_KIND_EPHEMERAL`.
- **Limits:** `ENVELOPE_MAX_BYTES` (default 64 KiB). Decoders reject oversized, expired or unknown-major-version packets.
- **Details (ADR 0006):**
  - use the codecs in `@pingdost/protocol` (size, version, expiry and required-field checks), never raw `toBinary`/`fromBinary`;
  - Content is padded to 256 B / 1 KiB / 4 KiB / 16 KiB buckets inside the ciphertext;
  - WS errors carry `@pingdost/shared-types` `ErrorCode` strings, the same codes as REST problem+json;
  - golden vectors live in `@pingdost/test-fixtures/protocol/v1.json`.

## A5. End-to-end encryption
- **Gate:** Phase 2 (core + license matrix + ADR, **user approval required**) and Phase 3 (Android native proof). No chat code ships before both.
- **Chosen: vodozemac 0.11.1** (Matrix.org, Rust, Apache-2.0, audited). **ADR 0003, accepted 2026-10-18.**
  - **Olm** v1 (Double Ratchet + 3DH) for per-device 1:1 sessions. One-time keys plus a fallback key, published via the key directory, give asynchronous prekeys.
  - **Megolm** v1 for groups. The outbound session rotates on every membership change (mandatory on removal) and every 100 messages / 7 days. Room keys are shared to each member device over Olm.
  - Megolm does not reject replays, so the engine rejects seen (sessionId, messageIndex) pairs. Repeated pre-key messages are routed by `prekeyMessageSessionId()`.
  - Why not MLS: MLS requires totally ordered commits, which breaks under offline/mesh delivery. Why not libsignal: no official RN or web builds. Both are scored in the Phase 2 matrix anyway.
- **Bindings:** a Rust wrapper crate `crates/pingdost-crypto` with a narrow uniffi API, built with **uniffi-bindgen-react-native (ubrn)**.
  - Android/iOS (ADR 0005): the ubrn **`jsi2`** flavour. `packages/crypto-native` ships `libpingdost_crypto.so` (built locally, git-ignored) plus committed TypeScript bindings; the app loads it through the `@ubjs/react-native` JSI player Turbo Module, which must be a direct app dependency.
  - Web and Node get the `wasm2` target (proven in Phase 2 on a Windows host; generated bindings and `.wasm` are committed in `packages/crypto/src/generated/`).
  - Both generated bindings have the same API, so one wrapper (`createBindingsProvider` in `@pingdost/crypto/core`) serves both.
  - Fallbacks: the classic ubrn `jsi` flavour (per-library C++ Turbo Module) for native; wasm-bindgen/wasm-pack for web.
  - Either way, consumers see only the `CryptoProvider` interface in `packages/crypto`. `@pingdost/crypto/conformance` holds the provider-independent scenarios, test vectors and interop protocol.
- **Multi-device:** messages are encrypted per recipient device, **including the sender's own other devices** (linked browsers), so every device stays in sync.
- **Verification:**
  - Each account has one Ed25519 **account identity key**, created on the primary phone and separate from the device Olm accounts. It signs each device's keys (a device certificate).
  - Safety numbers/QR codes are derived from both parties' account identity keys (display encoding only; proposed in ADR 0003, finalized in Phase 10).
  - Key changes produce a visible "safety number changed" notice.
- **Attachments (ADR 0004, accepted):**
  - XChaCha20-Poly1305 under the STREAM construction (RustCrypto `chacha20poly1305` + `aead-stream`) inside `crates/pingdost-crypto`, so one implementation runs on every platform.
  - A fresh random key and nonce prefix per file, 64 KiB chunks.
  - libsodium secretstream was dropped because react-native-libsodium only exposes it on web.
  - The manifest (scheme, key, nonce prefix, sizes, mime, `ciphertextSha256`, `chunkHashListSha256`) travels inside E2EE `Content`.
- **Backup rule (ADR 0003):**
  - Back up only the account identity key and Megolm inbound sessions.
  - Never restore a device Olm account, Olm sessions or outbound Megolm sessions. A restored device is a new device certified by the identity key.
- **Mesh first contact:** clients cache contacts' device identity and fallback keys while online, so Olm prekey messages can be created offline. A direct nearby handshake is the other option.
- **Local at rest:**
  - **Mobile:** SQLCipher DB key and Olm pickle key in `expo-secure-store` (Android Keystore).
  - **Web:** a non-extractable AES-GCM `CryptoKey` stored in IndexedDB encrypts sensitive records and pickles. The docs must state that browser protection is weaker than native.
- **Never** invent protocols. A new primitive use needs an ADR. Keys, OTPs, recovery phrases and plaintext never reach logs, analytics or push.

## A6. Mobile (Android first)
- **Expo** (latest SDK at Phase 3) with **dev builds**, run locally via `npx expo run:android` (Android SDK + JDK 17 are installed). No Expo Go and no EAS needed for Android.
  - **Load the `expo:expo-overview` skill before Expo work.**
- **Identifiers:** Android package and iOS bundle ID `com.pingdost.app`; URL scheme `pingdost`.
- ⚠ **ABIs:** `arm64-v8a` and `x86_64` (emulator) only, because the ubrn JSI player ships only 64-bit builds (ADR 0005). 32-bit-only phones are not supported for now.
- **Backups:** `android:allowBackup="false"`. Android Auto Backup must not copy the encrypted DB or pickles: ADR 0003 forbids restoring Olm state, and Keystore-wrapped keys do not restore anyway. Recovery uses the Phase 19 backup instead.
- **Navigation and UI:** Expo Router (`(auth)` and `(app)` groups); NativeWind with `@pingdost/ui-tokens`; light and dark themes.
- **Local DB:** `expo-sqlite` with config-plugin `useSQLCipher: true` and `enableFTS: true`.
  - A raw 32-byte key (`PRAGMA key = "x'…'"`) from SecureStore; opening checks `PRAGMA cipher_version`, because plain SQLite would ignore the key silently.
  - Raw-SQL repositories plus a migration runner keyed on `PRAGMA user_version` (`apps/mobile/src/db/migrate.ts`; `STRICT` tables).
  - Tables: REQ §14.1 entities plus `crypto_store` (pickles) and an FTS5 table.
- **Files:** `expo-file-system` (new File API, chunked reads, no base64 for big files). Attachments are stored **as encrypted files**; plaintext is decrypted to a temp cache only for viewing.
- **Libraries, by phase:**
  - Phase 3: crypto Turbo Module (ubrn).
  - Phase 10: FlashList.
  - Phase 12: expo-notifications (FCM token + background task).
  - Phase 15: expo-image-picker, expo-document-picker, expo-audio, expo-video, react-native-compressor (re-validate).
  - Phase 16: expo-camera (QR).
  - Phase 21: nearby Expo module in Kotlin.
  - Phase 26: react-native-webrtc.
- **Background:** FCM high-priority data messages wake the app for fetch. The mesh relay runs in an Android foreground service (`connectedDevice`) while relaying is enabled.

## A7. Web
- **Stack:** Vite + React + TS. React Router, TanStack Query, Zustand. Tailwind v4 + shadcn/ui with `@pingdost/ui-tokens`. Dexie (IndexedDB); never localStorage for history.
- **Install and push:** vite-plugin-pwa (manifest + service worker) for install and Web Push.
- **Crypto:** WASM crypto loaded lazily. A single-tab leader (Web Locks API) owns the WebSocket and the engine; other tabs follow via BroadcastChannel.
- ⚠ **Web devices authenticate only through QR pairing** from the primary mobile device (REQ §13.1). There is no password or Google login on web.
- **Hosting:** Cloudflare Pages (free), with a strict CSP.

## A8. Conventions
- **IDs:** UUIDv7 for users, devices (generated by the client), messages, packets, groups, attachments and pairing. `envelopeId = UUIDv5(messageId, recipientDeviceId)` under a fixed namespace (ADR 0006).
  - 16 bytes in protobuf; canonical lowercase strings in REST and storage.
- **Time:** epoch milliseconds (int64 in protobuf, number in TS). protobuf-es exposes int64 as `bigint`, so convert at the protocol boundary.
- **Sizes:** `ATTACHMENT_MAX_BYTES = 104857600`. The UI formats with binary units labelled "MB" (1 MB = 1,048,576 bytes), consistently everywhere.
- **Message states:** exactly REQ §8.3; UI copy follows REQ §11.6. "Delivered" requires a recipient-device receipt.
- **Testing:**
  - unit tests: `pnpm test`;
  - integration tests against docker-compose: `pnpm test:int`;
  - device checks are listed per phase.
  - Every REQ §19 criterion gets a test or a documented manual check (traceability is finished in Phase 27).
- **Commits:** at the end of each phase, `phase NN: <title>`. Conventional commits inside a phase are optional.

## A10. Security & privacy rules (always on)
- Never log, persist in plaintext, or send to analytics or push: message text, attachment bytes or keys, private or identity keys, recovery phrases, OTPs, passwords, access or refresh tokens, or SDP beyond what is needed.
- Server secrets are never bundled into the web or mobile apps. Only `EXPO_PUBLIC_*` / `VITE_*` values from `@pingdost/config/public` may reach clients.
- Rate-limit: auth, OTP, username lookup, key claim, WS events, uploads, pairing, call invites, mesh rendezvous.
- **Privacy wording** (REQ §1, §5.4): "no permanent server-side chat history". Never claim "no data touches servers".
- Dependencies must use permissive or OSI licenses compatible with the project license, **AGPL-3.0-or-later** (ADR 0001). No GPL-2.0-only code.

## A12. Platform scope
- **Now:** Android + web.
- **iOS:** deferred to Phases 28–30. Keep code platform-neutral where it costs nothing: Expo config for iOS present, no Android-only assumptions in shared packages.
- The user has 2+ Android phones and no Mac or iPhone. Mesh 3-device tests use the Node simulation until a third phone is available.
